## Фільтри

Розмір, колір, бренд, стать, сезон, матеріал, камуфляж, клас захисту, форм-фактор, сумісність, основа сітки та предметні характеристики. У UI показуються лише доступні значення. Ціна й наявність працюють окремо.

## PIM

Передавати canonical_category_id. Невідомий або батьківський ID відхиляється до змін товару; помилка записується у rubizh_category_sync_errors. Старі повні category paths підтримуються через mapping. Дерево постачальника не створює нові канонічні категорії.

## UI та банери

Два рівні: розділ → тип товару. Компактні картки з лічильниками на телефоні та комп’ютері. Банери прив’язані до category_id. Для порожніх категорій немає пунктів меню; сторінки відомих категорій залишаються доступними.

## Межі перевірки

Це перевірка копії публічного асортименту, а не звіт після міграції живої бази. При встановленні перевіряються всі рядки бази, включно з неопублікованими товарами та приватними зв’язками PIM. Потенційні дублікати перевіряються за supplier_id + external_id, якщо ці поля присутні; картки не зливаються і не видаляються.

Повний приватний backup усіх таблиць (DDL + рядки) та фактичних файлів media створюється поза web root. Потоковий запис зменшує витрати пам’яті. Откат зв’язків перевіряє контрольні суми та відмовляється затирати пізніші зміни PIM.
