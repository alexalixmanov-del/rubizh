## Простым языком (для владельца)

### Что увидит покупатель

- **Оплата только картой через monobank.** Наложенный платёж убран полностью. Оплата открывается, когда наличие подтверждено: при точном остатке у поставщика — сразу после оформления, иначе — после подтверждения менеджером (предзаказ, «под заказ», уточнение размера). Возврат со страницы банка сам по себе не считается оплатой — только подписанное уведомление банка.
- **Фото по цвету.** При выборе цвета показываются только фото этого цвета; если их нет — честная заглушка вместо чужих фото.
- **Комплекты (правила K1–K6, утверждены владельцем 2026-10-11).** Цена комплекта — только если в комплекте вещи минимум из двух основных разделов конструктора; по одной единице каждой модели на комплект (N — «для подразделения»), лишние штуки — по рознице. Подсказка «Додайте річ ще з одного розділу, щоб отримати ціну комплекту». Готовые комплекты не изменились.
- **Конструктор комплекта** с пошаговой подсказкой при первом визите; понятные статусы слотов.
- **Главная, каталог, поиск** — одна главная кнопка, поиск не «теряет» результаты из-за пробелов, мобильные карусели категорий, «Недавно переглянуті».
- **Кабинет:** карточки заказов с количеством товаров, отдельно оплата и доставка; видна только настоящая ТТН Новой почты (14 цифр); понятный статус «Оплата після підтвердження».
- **Вход по SMS** защищён от перебора и злоупотреблений (лимиты на номер, адрес и сутки). Сам вход по SMS остаётся выключенным до живой проверки (этап 6).
- **Мобильная скорость:** CSS первого экрана уменьшен на ~30%; основная проблема (долгая отрисовка первого экрана) ещё не решена — [PL-2](PRE_LAUNCH_BLOCKERS.md#pl-2).

### Что изменится в работе

- **CRM для персонала** (`/crm/`): роли Владелец / Менеджер / Логистика / Только чтение, подтверждение наличия, счета, отправки, возвраты, заметки, аудит действий. Денежные действия (возврат, ручная сверка, изменение цены) — только владелец и только при недавнем входе. Открыть CRM персоналу — после этапа 4 ([PL-4.4](PRE_LAUNCH_BLOCKERS.md#pl-4)).
- **Резервы товара** снимаются автоматически при отмене, возврате и полном возврате денег; оплаченные — закреплены.
- **Счета monobank** с неизвестным результатом не «зависают» и не считаются оплаченными без подтверждения банка; повторная оплата возможна до исходного срока.
- **ТТН с неизвестным результатом** (обрыв связи с НП) сверяется по маркеру; повторное создание без проверки запрещено.
- **Синхронизация из PIM:** старый способ выключен по умолчанию; новый (контракт 3) готов, но включается отдельной командой только на этапе 5. AUTOPRICES не используются.
- **Выкладка и откат** — по проверенному пакету с контрольной суммой; откат кода одной командой, данные — из бэкапа; всё отрепетировано на копии production-версии.
- Перед запуском обязательно: смена ключей PIM и cron, ответ хостинга о прокси, проверка бэкапа — [PRE_LAUNCH_BLOCKERS](PRE_LAUNCH_BLOCKERS.md).

## Технический список

### Каталог и PIM
- Pricing policy v1: серверная цена/пол/опт, атомарная синхронизация, цены `DECIMAL(14,2)` (схема 4).
- PIM contract 3: аддитивная схема (`pim_v3_schema=2`), атомарные пакеты с повтором и защитой хеша, MODEL → COLOR → SIZE → SKU, галереи по цвету, публичный DTO-whitelist; включение только `dev/pim-v3-enable.php`; сброс каталога `dev/pim-v3-catalog-reset.php`.
- R1: legacy-синхронизация выключена по умолчанию, данные контракта 3 защищены от legacy-записей.
- PIMC-12/13: проверка фото и валюты на границе контракта.

### Заказы, деньги, логистика
- P0: статусы резервов, append-only аудит заказа (`rubizh_order_audit` + триггеры), раздельные состояния заказа/оплаты/отправки.
