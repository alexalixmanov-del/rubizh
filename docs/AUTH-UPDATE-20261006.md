# Компактный вход и подготовка подключений · 06.10.2026

## Что изменено

На телефоне фото занимает 116 px вместо 236 px. Форма и кнопка входа расположены выше; поля сохраняют размер текста 16 px и удобные кнопки. При подтверждении SMS или email фото скрывается. Светлая тема, логотип и существующие способы входа сохранены.

Приватная конфигурация авторизации поддерживает переменные окружения. Настройки из существующего `auth/config.php` продолжают работать. Пустые заглушки Monobank и Новой почты больше не стирают ключи из `api/config.php`. Успех TurboSMS проверяется для конкретного номера и только при наличии ID сообщения.

## Установка обновления

1. Сохраните резервную копию текущих файлов и базы, особенно `api/config.php` и `auth/config.php`.
2. Распакуйте `Rubizh-login-and-integrations-20261006.zip`. Загрузите **содержимое** `rubizh-update/` в существующий корень сайта с заменой одноимённых файлов. Не создавайте на хостинге дополнительную папку `rubizh-update/`.
3. Папку сайта, приватные настройки, фотографии и базу не удаляйте. `config.sample.php` — пример, он не должен заменять действующий `config.php`.
4. Очистите кеш хостинга/CDN и обновите браузер. CSS входа имеет новую версию `v=2`.

Основные файлы обновления: `auth/index.php`, `auth/login-view.php`, `auth/login-refresh.css`, `auth/identities.php`, `auth/phone.php`, `auth/config.sample.php`, `api/mono-private.php`, `api/np-private.php`.

В архиве также находятся оба `assets/hero-*.2026100602.webp` — фотографии для страницы входа.

В `dev/` также находятся две команды для запуска через SSH: `check-services.php` и `init-auth-secret.php`. Они закрыты от HTTP-доступа правилом сайта и собственной проверкой CLI. Их не нужно открывать через браузер.

## Подготовка локального секрета и проверка

Через SSH из корневой папки сайта:

```sh
php dev/init-auth-secret.php
php dev/check-services.php
php dev/check-services.php --remote --database
```

Первая команда создаёт случайный ключ подписания кодов в `auth/config.php`, только если действующего ключа нет. Существующие настройки сохраняются, значение ключа не выводится, права файла — 0600. Повторный запуск действующий ключ не меняет.

`check-services.php` проверяет наличие конфигурации и расширений PHP. С `--database` выполняется только `SELECT 1`, без создания таблиц. С `--remote` читаются баланс и список отправителей TurboSMS, реквизиты merchant Monobank и список отправителей НП. Не отправляются сообщения, не создаются счета, заказы или накладные. Код завершения 2 означает недостающую настройку/расширение либо проблему проверки. Успешная проверка API не подтверждает доставку SMS/письма, оплату или вход через Google.

После настройки включите `sms_enabled` / `RUBIZH_SMS_ENABLED=true`. Google требует подключённой проверки телефона; включите `google_enabled` / `RUBIZH_GOOGLE_ENABLED=true` после настройки OAuth. `auth_secret` должен быть постоянным, не короче 40 символов; его можно создать первой командой. Ключи и пароли не публикуются в GitHub или архивах обновлений.

## Проверка запуска

На своём тестовом номере проверьте получение SMS, неправильный код, повторную отправку после минуты, вход и сохранение сессии. Затем проверьте настоящее письмо и возврат из Google в тот же кабинет. Отдельно проверьте тестовый заказ, уведомления, справочник НП, тестовую оплату и её подтверждение webhook.

На облачном окружении прошли 23 браузерных и 8 серверных проверок с изолированными данными. Скриншоты SMS и Google — просмотр оформления; настоящие SMS, письма и платежи в этой проверке не отправлялись. Боевой запуск требует доступа к хостингу и действующих приватных настроек.

Предоставленные ключи Monobank и Новой почты проверены отдельными запросами чтения: оба сервиса подтвердили доступ, НП вернула одного отправителя. Платежи и ТТН не создавались. Google Client Secret сохранён только в приватной конфигурации облачного рабочего каталога; в этом архиве его нет. Перенос конфигурации и проверка настоящего входа требуют доступа к хостингу.
