# Исправления конструктора, каталога и кеша

Базовое обновление установлено на rubizh.shop через WebSSH: пользователь подтвердил установку исходников, ремонт 2960 товаров, перенос 40 товаров в правильные категории и прогрев трёх наборов кеша без ошибок. У 109 товаров ещё нет подтверждённых характеристик. PHP 8.2.33, необходимые расширения и MySQL проверены на хостинге. API Monobank, Новой почты и TurboSMS прошли проверку; настоящий вход, доставка писем, оплата и выпуск ТТН проверяются отдельно. Внешнее SSH/SFTP-подключение из облачного окружения не установлено.

В архив добавлена настройка ТТН от владельца с пяти складов, включая Кіборг (Вінниця, №9 до 30 кг и №36 свыше 30 кг). После установки новой версии выполните `php dev/configure-np.php --interactive --apply`: [инструкция](NP-DROPSHIPPING-20261006.md). Команда сохраняет резервную копию и не создаёт накладных. Наложенного платежа у магазина нет.

## Что изменилось

- Рекомендации фильтруются по доступности, размеру и сезону **до** выбора первых трёх товаров. Убаксы и куртки имеют приоритет перед футболками. Рюкзак с клапаном для шолома относится к спорядженню.
- В пустых слотах показаны настоящие рекомендации с фото, ценой и кнопкой добавления. Одежда и обувь без подтверждённого размера исключены.
- При открытии конструктора загружается один общий список товаров вместо восьми параллельных каталогов со сложными фильтрами. Полные фильтры слота загружаются при его открытии.
- В контактах снова указан `info@rubizh.shop`. Сопутствующие товары к перчаткам ограничены подходящими аксессуарами; QD-антабки и шапки ДСНС исключены.
- Характеристики восстанавливаются из сохранённых атрибутов и явных строк `Матеріал: ...`, `Розміри: ...`, `Кольори: ...` в описании поставщика. Материал, класс защиты, размеры и медицинские сертификаты не угадываются. Например, в публичном описании MECHANIX THE ORIGINAL есть размеры и цвета, но нет состава ткани.
- При импорте одежда с очевидным названием, ошибочно попавшая в `Маскування`, получает соответствующий раздел одежды. Маскувальные костюмы, кікімори, маскхалаты и пончо сохраняют свою категорию. Для уже опубликованных строк есть отдельный ремонт с резервной копией.
- Фильтры размеров считаются одним простым запросом и нормализуются в PHP вместо повторения больших REGEXP/JSON-выражений в MySQL. Ценовые диапазоны считаются одним агрегатом вместо пяти запросов.
- Категории, каталог и список товаров конструктора сохраняют предыдущую версию и ставят обновление в очередь. Старые данные выдаются максимум пять минут с первого запроса после смены версии. Фоновый работник обновляет их; при сбое после этого срока кеш строится обычным способом. Оформление заказа проверяет актуальные цены и варианты отдельно.
- Полный HTML больше не кешируется отдельно: дешёвый шаблон рендерится на основе кешированных данных. Личные настройки и тема не сохраняются в общем кеше. Холодный запрос без предыдущей копии ещё может потребовать построения; поэтому нужен предварительный прогрев и cron.

## Установка исходников

Полный архив `downloads/Rubizh-redesign.zip` не содержит ключей, приватных конфигов, базы или папки фотографий. Установщик `dev/deploy-update.sh` проверяет SHA256 архива и PHP-синтаксис на хостинге, сохраняет предыдущие файлы вне www, сохраняет старые ключи из приватных файлов и не заменяет `api/config.php`, `auth/config.php`, настройки продавца, кеш и фотографии содержимым архива. При ошибке копирования/проверки исходники восстанавливаются. Старую базу этот установщик не меняет.

Пример после загрузки проверенного архива и установщика:

```bash
bash /tmp/rubizh-deploy.sh /home/xk589064/rubizh.shop/www /tmp/rubizh-update.zip ACTUAL_SHA256
```

`ACTUAL_SHA256` заменяется проверенной контрольной суммой конкретного архива из сообщения с установкой. Не используйте случайную контрольную сумму или изменяемую ссылку на непроверенный архив.

## База и фоновые обновления

После установки, из `/home/xk589064/rubizh.shop/www`:

```bash
php dev/install-catalog-indexes.php
php dev/repair-catalog.php
```

Вторая команда только показывает количество предлагаемых изменений. Для применения в рамках задачи исправления каталога:

```bash
php dev/repair-catalog.php --apply
php shop/cache-worker.php
```

Ремонт сохраняет изменяемые строки в `../rubizh-private-backups/` с правами 0600, затем выполняет изменения транзакцией. При параллельном импорте транзакция отменяется. Уже сохранённые характеристики не затираются догадками. Количество товаров без подтверждённых характеристик выводится отдельно; этим товарам ещё нужны данные поставщика/PIM. Ремонт не создаёт отсутствующие товары, размеры, остатки или медицинские позиции.

Добавьте в cron задачу раз в минуту, сохранив существующие задачи:

```text
* * * * * cd /home/xk589064/rubizh.shop/www && php shop/cache-worker.php >> ../rubizh-cache-worker.log 2>&1
```

Работник использует блокировку, не запускает одновременные копии, предварительно греет общие страницы и обрабатывает очередь. Это обязательная часть фонового обновления; загрузка исходников сама cron не добавляет.

## Приватные сервисы

Приватный JSON с уже полученными ключами передаётся отдельно от GitHub и загружается **рядом с www**, например `/home/xk589064/rubizh.shop/Rubizh-private-integrations.json`. Никогда не размещайте его внутри публичного www.

```bash
php dev/configure-services.php --file=/home/xk589064/rubizh.shop/Rubizh-private-integrations.json
php dev/check-services.php --database --remote
```

Существующие настройки базы, поставщиков, почты и ключ подписи сохраняются, приватные файлы получают права 0600. Платёжные и почтовые проверки не заменяются заявлением «всё работает».

Оставшиеся токен TurboSMS и пароль почты можно ввести прямо на своём хостинге, без отправки в чат:

```bash
php dev/configure-services.php --interactive --enable-auth
php dev/check-services.php --database --remote
```

В WebSSH ввод токена и пароля скрыт. TurboSMS: `Шлюз (API) → Настройки API`. Отправитель `RUBIZH`; статус регистрации у операторов означает временную подмену имени общим отправителем. Вход Google требует работающего SMS и OAuth redirect URI `https://rubizh.shop/auth/google.php`. Наличие ключа НП подключает справочник, но создание ТТН требует подтверждённых отправителя и точки отправки. Флаги эквайринга/ТТН установщик не включает автоматически.

## Robots и реальные проверки

Публичный robots.txt на момент проверки содержал `BEGIN adm.tools Managed content` с `Disallow: /` для ряда ИИ-ботов. Этот управляемый блок нужно отключить соответствующей настройкой в панели adm.tools, иначе хостинг может вернуть его после перезаписи файла. Проверьте публичный `/robots.txt` после настройки. Файл проекта уже содержит разрешённые публичные маршруты и запреты личных/служебных разделов.

В облаке прошли 39 проверок: 24 браузерные и 15 серверных, включая рекомендации с проблемными вариантами, кеш/очередь/ограничение устаревания, источник характеристик, категории, приватную конфигурацию и установку с сохранением настроек. Проверен синтаксис 80 публичных PHP-файлов. Эти проверки не подтверждают снижение задержек на хостинге: нужны повторные замеры после установки, индексов и cron. Настоящие SMS, письма, вход Google, платежи/webhook и ТТН ещё требуют проверки на хостинге.
