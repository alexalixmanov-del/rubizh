# Исправления аудита — 7 октября 2026

Обновление исправляет ошибки кода, найденные при проверке rubizh.shop. Установка исходников и проверка реальных внешних сервисов — отдельные этапы.

## Поведение после установки

- Новый заказ ждёт подтверждения наличия менеджером. monobank не получает запрос создания счёта при оформлении. После подтверждения покупатель получает письмо со ссылкой на оплату; срок оплаты и напоминание начинаются с этого момента. Подтверждение наличия не отмечает карточную оплату как полученную.
- Фильтры размеров канонизируют варианты один раз, затем используют индекс SKU. Фильтр наличия согласован с серверной проверкой покупки: неподтверждённые размеры одежды и обуви исключаются, настоящее количество 0 не считается наличием.
- Неизвестный остаток подписан «За даними постачальника» и не получает ложный индикатор «Мало залишилось · 0».
- Фото со статусом `ok` проверяются по физическим файлам. Пропавший оригинал или миниатюра возвращается в очередь. Дубликат не признаётся готовым по отсутствующему файлу; запись WebP атомарна. Временная ссылка поставщика используется только до загрузки локального изображения.
- В основных рекомендациях комплекта исключены крепления, каверы, камеры, камербанды, панели и учебные медицинские изделия. Фильтрация происходит до ограничения выборки. Запросы используют общие правила слотов и подтверждённый размер.
- Размеры идут S, M, L, XL, 2XL, 3XL. Габариты и варианты аксессуаров подписаны соответственно. Характеристики дополняются подтверждёнными цветами, размерами и единицей продажи; неизвестный бренд не заменяется названием магазина.
- Пустая корзина показывает переход в каталог; оформление скрыто. Сравнение сохраняется после перезагрузки. Плашка сравнения и ссылки рекомендованных товаров доступны с клавиатуры.
- Упоминания условий наложенного платежа убраны из покупательских текстов и оферты. Sitemap использует фактическое публичное дерево. Более конкретные Allow в robots открывают публичные страницы ИИ-поисковикам даже при добавленном хостингом Disallow: /.
- Кеш версии v3 исключает использование ответов со старой логикой. Фоновое обновление и проверка фотографий работают через общий automation-worker.

## Проверки

Полный набор: 78/78 тестов, включая Chromium на мобильных и настольных экранах, обе темы, очереди на MariaDB, идемпотентность оплаты после подтверждения и восстановление фотографий. После заключительного согласования PHP-правил слотов повторно прошли 11/11 целевых проверок размеров и регрессий аудита. Отдельно проверена безопасная замена старого cron-задания: сохранение остальных задач, повторный запуск и отказ хостинга. Синтаксис всех PHP-файлов проверен на PHP 8.4; установщик дополнительно проверяет PHP-файлы интерпретатором хостинга перед заменой.

На локальной MariaDB с копией 2457 публичных товаров и 7336 вариантов, без кеша: каталог 0,7 с; одежда L 0,7 с; L по всему каталогу 1,2 с; наличие 1,5 с; обувь 43 + олива 0,1 с; данные конструктора 0,3 с. Это измерения локального окружения, не обещание такой же скорости на хостинге.

## Установка

`dev/install-audit-update.sh` скачивает закреплённый архив, проверяет SHA-256 и использует `dev/deploy-update.sh` для частной резервной копии и сохранения текущих настроек. Затем готовит таблицы очередей, индексы, исправляет категории и исходные характеристики, ставит отсутствующие фото на загрузку и прогревает публичный кеш. Платежи, письма и ТТН установщик не создаёт. `install-automation-cron.sh` пытается заменить только задания этого магазина, сохраняя остальные; если хостинг не разрешает читать crontab, изменений расписания нет и команда для панели выводится отдельно.

Старое задание только для cache-worker нужно заменить общим заданием с запуском каждую минуту:

```sh
RUBIZH_PHP_BIN=/usr/local/php82/bin/php bash /home/xk589064/rubizh.shop/www/shop/automation-worker.sh
```

Это обрабатывает предусмотренные сайтом очереди писем, платежей, статусов посылок и фото. Защита от параллельного запуска сохраняется.

Проверка без отправки писем и создания заказов:

```sh
cd /home/xk589064/rubizh.shop/www && /usr/local/php82/bin/php dev/check-launch.php --smtp
/usr/local/php82/bin/php dev/catalog-health.php
```

## Что зависит от внешних данных

- Удалённые исходные фото с HTTP 404 требуют актуальных ссылок/оригиналов поставщика. Повторная загрузка не может восстановить отсутствующий источник. `catalog-health.php` выводит число ошибок и первые товарные slug без ключей, источников и данных покупателей.
- Настоящие размеры, бренд, материал, сертификаты и недостающий ассортимент должны поступить от поставщика/PIM. Код не придумывает эти сведения и не открывает покупку неподтверждённых размеров.
- GA4 и Meta требуют настоящих идентификаторов. Пример команды после получения IDs: `php dev/configure-analytics.php --ga4=G-... --meta=...`. Она сохраняет настройки с частной резервной копией; отслеживание включается после согласия посетителя.
- Реальная доставка email/SMS, оплата с callback, авторизованный кабинет и выпуск ТТН требуют контрольного заказа на хостинге. Успешные тесты и SMTP AUTH не доказывают получение письма покупателем.
