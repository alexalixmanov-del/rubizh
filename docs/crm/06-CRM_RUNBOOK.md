# CRM РУБІЖ — эксплуатация (runbook)

Для владельца и администратора хостинга. Запуск — [16-CRM_GO_LIVE_CHECKLIST](16-CRM_GO_LIVE_CHECKLIST.md); ключи — [CONFIG §16](../release/CONFIG.md); архитектура — [01](01-CRM_ARCHITECTURE.md); роли — [03](03-RBAC_MATRIX.md); инструкция для сотрудников — [07](07-CRM_USER_GUIDE.md).

## 1. Из чего состоит

| Часть | Где | Примечание |
|---|---|---|
| Интерфейс | `$SITE/crm/` (сборка `crm.rubizh/dist`) | Статика, `no-store`, CSP без `unsafe-inline`, `noindex` |
| Staff API | `/api/staff/*` → `api/staff/index.php` → `staff/router.php` | Контракт `contracts/crm/crm-api.json`; ответы `{"data":…}` / `{"error":{"code","message","request_id"}}` |
| Бизнес-логика | `shop/*` (SITE) | CRM не дублирует правила сайта (A2) |
| Фоновая обработка | `shop/automation-worker.sh` → `staff/worker.php` каждые 60 с | Сверка оплат, автозадачи, уведомления, письмо OWNER о критичных событиях |
| Данные | БД SITE: `rubizh_crm_*`, `rubizh_staff_*`, `rubizh_wholesale_requests`, `rubizh_invoice_payments`, … | `meta.crm_schema = 3` |

## 2. Ежедневно

1. «Огляд» → «Потребує уваги»: не подтверждённые >30 мин, без ТТН >24 ч, оплаты на сверке, проблемные доставки.
2. «Платежі» → «Потребують звірки виписки» (ФОП-счета после срока оплаты, D-51) и «Потребують перевірки» (банк не подтвердил). Принять оплату по выписке может OWNER или ACCOUNTANT (повторный вход ≤15 мин).
3. «Клієнти → Оптові заявки» (D-54): заявки «Запит на прорахунок» с главной; ответ в течение рабочего дня.
4. «Сповіщення»: критичные — в первую очередь.

## 3. Инциденты

| Симптом | Причина | Действие |
|---|---|---|
| «CRM ще не увімкнено» | `crm_enabled` не `true` | Проверить `api/config.php` (шаг C7) |
| «CRM оновлюється. Спробуйте пізніше.» (`STAFF_SCHEMA_REQUIRED`) | Схема не v2 | `dev/migrate-crm.php --plan`, затем `--apply` (шаг C4) |
| «Двофакторна перевірка ще не налаштована на сервері.» | Нет `RUBIZH_CRM_SECRET_KEY` / `crm_secret_key` | Вернуть ключ из хранилища. **Новый ключ делает прежние TOTP нечитаемыми** — тогда всем OWNER/ACCOUNTANT выполнить `--reset-totp` (ниже) |
| Потерян телефон с автентификатором, резервные коды есть | — | Вход с резервным кодом (каждый код — один раз). Для нового телефона — `--reset-totp` (ниже) |
| Потерян телефон и резервные коды | — | На сервере: `$PHP dev/staff-user.php --reset-totp --email=<email> --reason="<причина>"` — 2FA удаляется, все сессии закрываются, запись `staff.totp_reset` в журнал; при следующем входе подключение заново и новые резервные коды |
| «Підключення двофакторної перевірки доступне за посиланням від власника» | Подключить 2FA можно только 72 ч после приглашения, сброса пароля или серверной команды (R4-07) | OWNER: «Співробітники → Скинути пароль» — ссылка снова разрешает подключение; для OWNER — `dev/staff-user.php --reset-totp` |
| Забыт пароль | — | OWNER: «Співробітники → Скинути пароль» (одноразовая ссылка на 2 ч, все сессии сотрудника закрываются). Единственный OWNER забыл пароль: на сервере создать второго OWNER (`dev/staff-user.php --role=OWNER`), из CRM сбросить пароль первому, затем при необходимости отключить второго |
| «Забагато запитів» | Лимит неудачных входов (IP + аккаунт) или 240 запросов в минуту на сессию | Подождать минуту. Лимит не блокирует коллег за общим офисным IP (R8) |
| Ошибка 500 у сотрудника | В ответе есть `request_id` | Лог PHP: `CRM failure <request_id> <класс> <файл:строка>`; детали наружу не отдаются |
| «Фонова обработка CRM повторно не вдалася» | `staff/worker.php` упал ≥3 раза подряд | Запустить `$PHP staff/worker.php` вручную, смотреть stderr; `rubizh_crm_cron_runs` — время последнего успеха |
| «Функція ще не підключена» | Live-флаг выключен (A9) | Ожидаемо до этапа 6 |
| Отправление «потребує перевірки» | НП не подтвердила результат (R6) | Карточка отправления → «Звірити з НП»; если результат неизвестен — решение OWNER с причиной |
| Платёж «потребує перевірки» | Банк не подтвердил (нет webhook / нет id счёта) | «Платежі → Потребують перевірки» → «Перевірити в банку зараз», затем «Позначити розглянутим» с причиной — только по данным кабинета банка |

## 4. Безопасность

- Сессия сотрудника: отдельная cookie `rubizh_staff` (Secure, HttpOnly, SameSite=Strict), бездействие 30 мин, максимум 12 ч; «Налаштування → Активні сесії → Завершити інші сесії».
- «Співробітники → Змінити → Активний»: снятие отметки закрывает все сессии сотрудника сразу; последнего активного OWNER отключить нельзя.
- Журнал — «Активність» (append-only): кто, роль, что, было/стало, причина, IP-хеш, `request_id`.
- Полный телефон клиента открывается кнопкой и попадает в журнал; полный экспорт — только OWNER, с причиной и повторным входом.

## 5. Резервное копирование и откат

Бэкап БД SITE включает все данные CRM. Откат кода — раздел «Откат» `GO_LIVE_CHECKLIST`; таблицы схемы v2 только добавлены, прежний код на них работает. Флаги откатываются копией `api/config.php`, сделанной перед изменением.

## 6. Тестовый стенд

`environment=staging`, `mono_mock=true`, `np_mock=true` — внешние сервисы заменены mock-ами с живым контрактом. Наполнение: `php dev/crm-synthetic.php --orders=520` (все состояния заказов через функции SITE/CRM); замер производительности — `--bulk=50000`. На production скрипт не запускается и сам отказывается работать.
