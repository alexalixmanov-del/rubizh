## Предлагаемый порядок удаления (после согласования)

1. **Этап A — git:** одним коммитом `git rm` кандидатов (без production-версий выше). Проверка: полный `npm test`, `qa-matrix` (вкладки без 404 на `assets/`), CI.
2. **Этап B — сервер:** только после следующего релиза, когда production перестанет ссылаться на `shop-client.2026101002.js` / `pim-v3-product.2026101002.js`; список удаляемых на сервере файлов — из этого документа, с резервной копией каталога `assets/` перед операцией.
3. **Откат:** этап A — `git revert <commit>`; этап B — восстановление из резервной копии `assets/` (файлы неизменяемые, по хешу/версии в имени).

Риск: внешние ссылки (письма, закладки) на старые картинки hero/категорий получат 404 после этапа B; в письмах (`auth/email-templates.php`) эти файлы не используются.
