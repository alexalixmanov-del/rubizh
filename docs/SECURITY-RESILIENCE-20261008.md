# Баннеры, скорость и защита магазина — 08.10.2026

Обновление подготовлено для существующего PHP/MySQL-хостинга. Оно не переносит
данные покупателей во внешний сервис и не подключает платные услуги.

## Что входит в обновление

- Подключены все 96 новых пронумерованных изображений по документу владельца.
  Для шорт использован исходный файл №8, для головных уборов — №7.
  Исходники занимали 217 149 506 байт; готовые WebP — 1 924 902 байта.
  Размер одного изображения 384×480, самое большое — менее 36 КБ.
- Реестр содержит 117 изображений категорий, включая ранее установленные.
  Портретные изображения заполняют компактные карточки в мобильной версии.
- Начальная подборка передаёт до 12 рекомендаций на слот вместо 40.
  Товары, входящие в опубликованные комплекты, добавляются отдельно.
  Полный каталог слота, поиск, фильтры и пагинация сохраняются.
- Баннер главной больше не загружается заранее на страницах каталога и комплекта,
  в том числе из скрытого шаблона до запуска интерфейса.
- Подготовленная схема исключает повторные CREATE/ALTER при обычных запросах.
  Установщик готовит таблицы и индексы через CLI, затем записывает версию схемы.
- Ограничены размеры фильтров, JSON, изображений и время публичных SQL-запросов.
  Публичное чтение допускает до 16 одновременных обработчиков, кабинет — 12,
  оформление — 8, перестройка кэша — 4. При перегрузке возвращаются 429/503
  с указанием времени повторной попытки.
- Перестройка кэша защищена от одновременного выполнения одинаковой работы.
  Число файлов блокировок фиксировано; периодическая очистка сокращает JSON-кэш
  до 512 файлов/64 МиБ. Это порог очистки, а не жёсткая дисковая квота.
- Повторное оформление с одним ключом запроса возвращает ранее созданный заказ.
  Остатки резервируются в транзакции. Товары и варианты блокируются в одинаковом
  порядке, чтобы встречные корзины не создавали взаимные блокировки.
- Callback Monobank проверяет формат и подпись; запрос без подписи не открывает
  пользовательскую сессию. Повторное получение публичного ключа ограничено.
- Загрузка фото поставщиков проверяет адреса и каждый редирект, запрещает
  обращения к локальным сетям/метаданным и фиксирует проверенный DNS-адрес.
- Добавлены CSP с nonce, защита от встраивания, HSTS для основного домена,
  запрет исполнения PHP в media и запрет доступа к служебным файлам.
  Текущий скомпилированный интерфейс всё ещё требует `unsafe-eval`; эту часть
  нужно убрать при последующей замене его шаблонизатора.
- Ошибки API не раскрывают внутренние исключения. В изменённых обработчиках
  журналируется класс и код ошибки вместо сообщения, способного содержать
  контактные данные. Профилировщик не записывает параметры URL.
- Файлы устанавливаются атомарно по одному, новые зависимости — раньше точек
  входа. Перед установкой проверяется синтаксис под PHP хостинга; предыдущие
  исходники сохраняются вне www. Это не атомарная замена всего приложения.

## Установка на существующий сайт

Используется [dev/install-banners-security.sh](../dev/install-banners-security.sh).
Он закрепляет архив за коммитом и проверяет SHA-256 перед извлечением.
Перед обновлением проверяет PHP и расширения; после сохранения предыдущих
исходников готовит таблицы и индексы, прогревает кэш и проверяет все восемь
слотов конструктора. Повторное перераспределение товаров по категориям не
выполняется. Данные покупателей не переносятся. Расписание cron не меняется.

Запуск проверенного скрипта в WebSSH:

```sh
bash /tmp/rubizh-install.sh /home/xk589064/rubizh.shop/www
```

Публикация архива на GitHub не означает установку на хостинге. После выполнения
нужны вывод установщика и повторный замер живого сайта; значения скорости ниже
относятся к версии до этого обновления.

| 32 клиента, 160 чтений | 159 ответов 200, один контролируемый 503; p95 163 мс |
| 8 повторных оформлений одного запроса | один заказ |
| 8 покупателей, остаток одной штуки | один заказ и одна резервация |
| Две корзины с обратным порядком товаров | два заказа, взаимных блокировок нет |
| Начальные рекомендации | 89 товаров, JSON 195 670 байт |

Это не нагрузочный тест производственного хостинга. Размеры пулов не являются
гарантией числа посетителей. Поддержка 10 000 одновременных покупателей не
подтверждена. Для предела нужны лимиты аккаунта у провайдера: CPU, память,
PHP-воркеры, MySQL-соединения, дисковые операции и условия ограничения нагрузки.
Команда `php dev/check-capacity.php` показывает доступные параметры без паролей,
но глобальные параметры MySQL не заменяют лимиты конкретного аккаунта.

## Мониторинг

После установки адрес `https://rubizh.shop/health.php` возвращает только
`{"ready":true}` с HTTP 200 либо `{"ready":false}` с HTTP 503.
Проверяется доступность базы, версия подготовленной схемы и успешное выполнение
cache-worker за последние 180 секунд. Сессия не создаётся, контакты не читаются.
Результат нельзя кэшировать в CDN. Для проверки сайта нужны также мониторы `/`
и `/shop/catalog.php?slot=body`: один health endpoint не проверяет отрисовку
интерфейса, платёжный провайдер или доставку писем.

У пользователя уже настроен ежеминутный запуск cache-worker. Обновление не
меняет расписание. Первый успешный запуск создаёт heartbeat. Если задача
остановилась, внешний монитор должен обнаружить это независимо от сайта.
Постоянный внешний монитор и доставка уведомлений в Telegram/email пока не
активированы: нужен аккаунт мониторинга и его контакты. Новый endpoint сам
уведомления не отправляет. Фоновые очереди писем и платежей дополнительно
проверяются `php dev/check-launch.php`; наличие cache-cron не доказывает,
что запущены остальные задачи.

## Данные покупателей — подключение отложено владельцем

Для внешней базы выбран Aiven Managed MySQL. Для отдельного закрытого хранилища
копий — Backblaze B2; для аварийных уведомлений — UptimeRobot. Тарифы и порядок
подключения: [отдельный документ](EXTERNAL-DATA-20261008.md).

Подготовлен общий механизм подключения с портом, таймаутом, проверкой CA и
TLS-сертификата сервера. Подключение без шифрования отклоняется. Рабочие
учётные данные можно будет поместить в `rubizh-private/database.php` вне www.
Это файл настройки подключения, не файл с покупателями. Без этого файла
текущая база продолжает использоваться. Перенос и удаление старых данных
в данном обновлении не выполняются. Сессии и существующие резервные копии
также потребуют отдельного переноса/очистки при выполнении этой задачи.
